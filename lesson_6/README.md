## 1. Редактор до настройки

В корне проекта можно создать `proba.py` с вызовами функций из `app/utils/formatter.py`
и `app/utils/text.py`. Для демонстрации проверки типов временно передайте значения
неподходящих типов, например `format_title(40)` и `format_kopeks("1250")`.

## 2. Включение режима basic

В проекте уже подготовлен файл `.vscode/settings.json` с настройкой
`python.analysis.typeCheckingMode: basic`.

## 3. Ошибки в редакторе

После включения режима `basic` Pylance должен подсветить аргументы неверного типа.
Для фиксации результата сделайте собственный скриншот в VS Code.

## 4. Панель Problems

Для демонстрации ошибки `normalize_name(42)` используйте функцию из
`app/utils/text.py`. После проверки верните корректный аргумент типа `str`.

## 5. Четыре режима

Проверьте один и тот же тестовый файл в режимах `off`, `basic`, `standard` и `strict`.
Количество сообщений зависит от версии Pylance и настроек редактора, поэтому
зафиксируйте фактические результаты, а не копируйте числа из чужого отчёта.

## 6. Проверка mypy

Установите зависимости и запустите:

```bash
python -m pip install -r requirements.txt
mypy proba.py
mypy app
```

## 7. Исправление

В `proba.py` оставлены корректные вызовы. Для проверки временно внесите ошибки,
запустите mypy, затем восстановите корректные значения и повторите проверку.

## 8. Проект без аннотаций

В `pyproject.toml` включено `disallow_untyped_defs = true`. Поэтому mypy сообщает
об ошибках для функций без аннотаций типов.

## 9. Тип результата

В `app/services/calculator.py` функция `grade_bounds` возвращает
`tuple[int, int]`. Проверить тип можно с помощью `reveal_type`.

## 10. Итог

Pylance помогает замечать ошибки типов прямо в редакторе, а mypy выполняет
статическую проверку из терминала. После исправления ошибок повторная проверка
должна завершиться без замечаний.

**Важно:** добавьте свои скриншоты в папку `img` и обновите этот отчёт по фактическим
результатам. Не оставляйте утверждения о проверках, которые лично не выполнялись.
